# Nook

Nook is a personal project for managing Herdr App themes, layouts, and mods.

## Directories

- `themes/`: Window and terminal themes. `Gruvbox Dark.json` was copied from the current Herdr configuration, with terminal colors from [Gruvbox Dark in iTerm2 Color Schemes](https://github.com/mbadolato/iTerm2-Color-Schemes/blob/master/schemes/Gruvbox%20Dark.itermcolors) and additional interface colors.
- `mods/`: Custom panels and interactions.
- `layouts/`: Layouts that reference custom mods.

## Development and installation

Herdr App loads its configuration from `~/.config/herdr-app/`, not directly from this project. The two directories currently contain separate files. The installation script copies the project's themes, layouts, and mods without deleting other files in the destination:

```sh
python3 scripts/install.py --dry-run
python3 scripts/install.py
```

If a destination file already has different content, the script stops without copying any files. After reviewing the differences, use `python3 scripts/install.py --force` to overwrite conflicting files. By default, the script uses `HERDR_APP_HOME` if set, or `~/.config/herdr-app` otherwise. Use `--home <directory>` to specify a destination. After installing a theme, select it in Herdr's theme picker.

Herdr updates its built-in mods and layouts. To customize one, first copy it under a new name and have the custom layout reference the custom mod. Symbolic links and hot reload have not yet been verified in this project.

## Automatic tab names

Each terminal pane's top bar shows its current Git branch when Herdr reports one, alongside the existing title, folder, status and pane controls. The branch follows that pane's current folder and displays its full name on one line without a fixed width cap or ellipsis. After updating, review the installation dry run and conflicts, install the changes, run `herdr-app check mods/nook-pane`, and check `herdr-app status`. In the `nook` layout, verify branches in different split panes, a non-repository folder, branch changes, and the existing split, zoom and close controls. The custom header is a snapshot of Herdr's built-in `pane` mod; compare it with upstream when updating Herdr.

The sidebar footer displays Settings and Add machine as icon-only buttons on one row, including when the sidebar is collapsed. Hover for their labels; the Settings icon retains the update indicator. The right side shows local time as HH:MM:SS, hidden when the sidebar is collapsed. After updating, review the installation dry run, install the files, run `herdr-app check ~/.config/herdr-app/mods/nook-footer`, and check both buttons, the clock, and the collapsed sidebar in the `nook` layout.

The bottom status bar is removed. The top tab bar shows the total number of blocked agents across all Spaces, including zero. The count uses the theme's attention color when agents need a reply; hover to see its meaning. Saved commands, New tab, Files and Changes use compact icon buttons with hover labels; the active panel is highlighted. After installation, verify the count while switching Spaces and when an agent needs attention, and check tab scrolling and panel buttons at narrow window widths.

The terminal icon beside the new-tab button opens Saved commands. In the `nook` layout, `⌘R` can open the same dialog: add `"cmd-r": "nook-tabs.saved-commands"` to the `"layout:nook"` section of Herdr's `keys.json`, preserving existing bindings. Add, edit, and delete named shell commands in the dialog; deletion asks for confirmation. The first command is selected when the dialog opens. Use ↑ / ↓ to cycle through commands and Enter to run the selected command; the selected command is highlighted and its name also appears below the list. Click a command row to select it. Keyboard execution is suspended while editing, confirming deletion, or starting a background command. Saving or cancelling an edit restores keyboard focus to the list. Run `node tests/saved-commands.cjs` for keyboard behavior checks, and verify selection, scrolling and Enter in the running dialog after installation. Commands are stored in Herdr's client-local shared state. Run opens a new tab in the Space and working directory captured when the dialog opened, on that Space's machine, using `sh -lc`. The machine must provide `sh`; command output appears in the new terminal. Review the installation dry run and destination differences before installing, then run `herdr-app check mods/nook-tabs`, `herdr-app check mods/nook-commands`, and `herdr-app status`. Verify adding, editing, running and deleting a harmless command in the running layout, including a remote Space if used.

Each saved command has a Foreground or Background run mode; existing commands default to Foreground. Background opens a normal terminal tab, then returns to the original tab if the new tab is still selected. Herdr currently selects newly created tabs, so the new tab may appear briefly. If you switch elsewhere during startup, your selection is kept. The command and its output remain available in the new tab. Background mode requires the `herdr-app` command on the local PATH. After updating, verify both modes with a harmless command, including output, failure handling, and switching tabs during startup.

The `nook` layout copies the current Herdr `main` layout and uses the custom `nook-tabs` mod. Select `nook` in the layout picker after installation. For an unnamed tab, the bar chooses the first agent pane, otherwise the first non-shell terminal, otherwise the first terminal, in pane order. It displays the agent's terminal title when available, otherwise the program name, then the current directory's last component, and finally the tab number. A manually named tab always keeps its name; clearing it returns to automatic display. The inferred name is not saved or sent to other clients. Pane focus changes do not change which split supplies the name.

After changing the mod or layout, rerun the install command (use `--force` only after reviewing destination differences), then check `herdr-app check ~/.config/herdr-app/mods/nook-tabs`, `herdr-app status`, and the displayed tab bar. To return to Herdr's built-in interface, select the `main` layout. The custom layout is a snapshot; to pick up later upstream layout changes, compare it with `main` and carry them over while retaining the `nook-tabs` reference.

## Spaces and editors

The `nook` layout also uses `nook-spaces`, based on the installed built-in Spaces mod. Expanded rows show the space name, agent status, Git branch, changed-file count, ahead/behind counts and multiple-tab count. Non-repositories show their current folder; `Git unknown` means the result is pending or unavailable, not a clean repository. Git data follows the built-in refresh strategy and can lag behind external edits. The first available terminal folder supplies the Git and editor location. Lucide icons supplied by Herdr are selected consistently from each space ID.

Expanded machine cards show CPU usage and used / total memory, refreshed every 10 seconds. CPU is sampled over approximately one second. On Linux, used memory is total minus `MemAvailable`; on macOS it is active, wired, and compressed pages. Values use GiB (displayed as GB). Offline machines and unsupported systems show unavailable. The row is hidden when the machine or sidebar is collapsed. After installation, verify both local and connected remote machines in the expanded Spaces sidebar and check that unavailable machines do not show old readings.

Hover over an expanded Space and click its pin to keep it at the top of its machine; click the highlighted pin again to unpin it. Pins are stored in Herdr shared state on this client and survive layout changes and restarts. Pinning changes the display order without changing the saved Space order; drag within the pinned or unpinned group to reorder. A worktree pinned separately from its main checkout is displayed as an independent row. To verify after installing, pin and unpin Spaces on each machine, drag within a group, and confirm the original group position returns after unpinning.

The package-pen icon opens the current folder in an installed VS Code or Zed on macOS. For a remote space, the picker looks up the machine's SSH target in `hc machine ls` and passes the remote path to the selected editor. Both editors must be able to SSH to that target independently of Herdr; VS Code also needs its Remote - SSH extension. The editors may prompt for authentication or install their remote server. SSH config aliases are supported. Custom `hc machine add --via` transports are not supported; use a normal SSH config alias. For VS Code, configure a nonstandard port in SSH config and add the machine with that alias. An absolute remote folder is required. An accepted launch does not mean the editor has connected successfully: check the editor window for connection errors.

The icon is from [Lucide](https://lucide.dev/) (ISC license; see Herdr's `icons/LICENSE-Lucide.txt`).

After updating, review `python3 scripts/install.py --dry-run`, install (use `--force` only after reviewing conflicts), and run `herdr-app check` for both `mods/nook-spaces` and `mods/nook-editor`. Check `herdr-app status` and exercise the picker in the `nook` layout. The layout and mods are snapshots of built-in code; compare them with Herdr's updates before incorporating upstream changes.

Right-click a Space and choose **Change icon** to browse the icon grid. The picker reads SVGs from Herdr's `mods/workspace-chrome` and `icons` directories each time it opens. Enter part of a name to filter; Enter selects an exact match or the sole result. Hover an icon to see its name and source. **Random** draws a preview from the current results. Use **Draw again** to redraw and **Use icon** to save the preview; closing the picker leaves the saved icon unchanged. **Automatic** restores the default. The selection is saved per Space in this client's shared state and persists across layout changes and restarts. Nested worktrees keep their branch icon until a custom icon is chosen; the compact sidebar continues to display numbers. Icons are drawn in the Space color.

After changes, review the installation dry run and destination differences, install the updated files, run `herdr-app check` on `nook-spaces`, `nook-space-menu`, and `nook-icon-picker`, and check `herdr-app status`. In the `nook` layout, check icon browsing, search, random preview, redraw, saving and Automatic, including a nested worktree. Verify persistence after restarting Herdr and confirm existing rename, worktree and close actions.

## Render performance

`nook-spaces` shares one snapshot of Spaces, panes, agents, and machine layouts across rows on each render, counting agents by Space once. Each render and 250 ms Git polling pass indexes tab ownership and the first available pane folder in one pass, preserving pane order across multiple tabs and the Space folder fallback. Folder lookup costs O(Spaces + tabs + panes) per pass instead of repeatedly scanning all panes for every Space. Worktree children are indexed by repository, rows by machine, and visible parents by pin group, avoiding repeated full-list scans during grouping. The snapshot is rebuilt on the next render, so live title, status, folder, and connection changes remain visible. Color assignment maintains running usage counts instead of rescanning every assigned color for each candidate. `nook-tabs` selects each tab's preferred terminal in one pass over panes, preserving the first agent, then first non-shell terminal, then first terminal in model order. Manual names keep priority.

Run `node tests/render-performance.cjs` from the project root for render regression checks with a minimal GPUI mock. It covers tab selection, live updates, agent counts, balanced colors, native collection read counts, and linear pane-field read bounds for 1, 100, and 1,000 Spaces. It also checks folder updates, pane order across tabs, worktree grouping, duplicate checkouts, pin partitions, and remote groups. This checks JavaScript behavior and call counts, not native layout, frame rate, or CPU usage. Also run `herdr-app check mods/nook-spaces` and `herdr-app check mods/nook-tabs`.

A before/after comparison using the same GPUI mock and one terminal pane per Space counted reads of each pane's `tab` field (lower is better):

| Spaces | Render before | Render after | Git poll before | Git poll after |
| --- | ---: | ---: | ---: | ---: |
| 100 | 15,150 | 100 | 5,150 | 200 |
| 1,000 | 1,501,500 | 1,000 | 501,500 | 2,000 |

The render also reads the native Spaces collection once instead of twice. These are operation counts, not frame-time or CPU measurements. Structural Space moves still use the existing command and retry path; the optimization targets folder lookup and grouping, not the cost of applying a reorder.

These commands check project sources; they do not install them. To apply an update, review the installation dry run and destination differences using the installation steps above. After installing, check `herdr-app status`, inspect a `herdr-app shot` capture, and exercise tab titles, Space selection, pinning, dragging, editor launch, and remote machine status in the running `nook` layout. Native interaction and performance measurements require that separate runtime verification.

## Files context menu

The Files tree includes a path search and Material Icon Theme file and folder icons (MIT; see `mods/nook-files/LICENSE-material-icon-theme.txt`). Search reads nested folders on the active Space's machine, including folders not expanded in the tree. Click a file result to preview it, or a folder result to reveal it in the tree; the context menu also works on results. Search skips `.git`, `node_modules`, `target`, `.venv`, `__pycache__`, `dist`, and `.next`, and is bounded to 500 entries per folder, 5,000 entries overall, 12 levels and 200 results. It reports incomplete searches and unreadable folders. Search waits 250 ms after typing and builds a shared in-memory path index with at most four directory reads in flight. Query changes reuse that index without directory reads; the local folder watcher and 10-second tree refresh invalidate it. Re-enter or edit the query after refresh to rebuild it. The index is scoped to the current machine and working directory and is not written into the project. Plain text matches any part of a path, ignoring case. Wildcard patterns match whole basenames at any depth when they contain no slash (for example `*.js` or `file?.txt`); patterns with slashes match root-relative paths (`src/*.js` for immediate children, `src/**/*.js` for any depth). `*` matches zero or more non-slash characters, `?` one non-slash character, and `**` crosses folders; `**/` also matches zero folders. Other characters are literal. Results appear when indexing finishes. Run `node tests/files-search.cjs` for matching, index reuse, bounded concurrency, limits, read failures and cancellation checks. Directory links follow the same behavior as the normal tree, subject to these bounds.

The tree shows the current Git branch and status letters for changed files and their parent directories: `?` untracked, `A` added, `M` modified, `D` deleted, and `U` conflicted. A directory with several kinds of changes shows one of its children's statuses. Git data refreshes with the existing file-tree polling and local folder watch; it may lag external changes. Deleted files are represented by their parent directory when the file is no longer present. Search and Git status operate on the focused terminal's current folder, including supported remote machines.

The `nook` layout uses `nook-files`, a snapshot of Herdr's Files panel. The file tree starts at the top without a separate Files title bar. The file tree stays above a read-only preview; select a file to show it below and drag the divider to resize the two areas; its last ratio is restored when the panel is reopened. Markdown files offer Code and Preview modes; the last chosen mode is remembered for this panel across files and app restarts. Both modes use the same bounded file content. Right-click a file or folder to open it in Zed or VS Code, or copy its path relative to the folder shown by Files (the focused terminal's current folder). The menu supports arrow keys, Enter and Escape. Opening uses the local macOS editor; remote paths use the same SSH target restrictions described above for Spaces. The editor may still need to authenticate or establish its remote connection.

After updating, run `python3 scripts/install.py --dry-run`, review any destination differences, and install with `python3 scripts/install.py` (add `--force` only for reviewed conflicts). Run `herdr-app check mods/nook-files` and `herdr-app check mods/nook-files-menu`, then check `herdr-app status`. In the `nook` layout verify search in collapsed directories, result previews and folder navigation, icons, Git branch and status, the menu on nested files and folders, clipboard contents, both editor launches, remote paths where applicable, file preview, split resizing, and folder expansion. Compare the snapshot with Herdr's built-in Files mod when incorporating upstream updates.

On macOS, selecting a local PNG, JPEG, GIF, WebP or BMP previews the original image. Herdr loads application-relative assets, so the panel stores byte-for-byte copies under `data/nook-files-originals/` in the active Herdr configuration directory. All projects share one cache of at most 16 images. Selecting an image makes it the most recently used; adding another image beyond the limit removes the least recently used cached image. Images with identical bytes and the same extension share a cache entry. Switching files or closing the panel does not clear the cache. The panel does not resize or re-encode images; `sips` reads dimensions and the UI fits them proportionally. This requires macOS and `python3`. SVG files continue to use the text preview; remote images show an unavailable message. Native decoder support determines which images render; animation playback has not been verified. Older thumbnail experiments used `data/nook-files-previews/` and are not part of this cache.

After updating, select images in the running panel and inspect a `herdr-app shot` capture, resize the split, and switch back to text and Markdown files. To verify original-file preservation, compare the source and temporary copy with `cmp` or SHA-256.

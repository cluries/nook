# Nook

Nook is a personal project for managing Herdr App themes, layouts, and mods.

## Directories

- `themes/`: Window and terminal themes. `Gruvbox Dark.json` was copied from the current Herdr configuration, with terminal colors from [Gruvbox Dark in iTerm2 Color Schemes](https://github.com/mbadolato/iTerm2-Color-Schemes/blob/master/schemes/Gruvbox%20Dark.itermcolors) and additional interface colors.
- `mods/`: Custom panels and interactions.
- `layouts/`: Layouts that reference custom mods.

## Development and installation

The `nook` layout includes an illustrated SVG preview for Settings → Look → Layout. The layout references `layouts/nook.svg`; keep the SVG and `layouts/nook.json` together when installing or updating. After installation, open Settings → Look and check the Nook card.

Herdr App loads its configuration from `~/.config/herdr-app/`, not directly from this project. The two directories currently contain separate files. The installation script copies the project's themes, layouts, and mods without deleting other files in the destination:

```sh
python3 scripts/install.py --dry-run
python3 scripts/install.py
```

Project files replace corresponding destination files when their contents differ; files that exist only in the destination are preserved. Use the dry run to review the files that will be installed. The script refuses to replace a destination symlink or other non-regular file. `--force` remains accepted for compatibility but is no longer needed. By default, the script uses `HERDR_APP_HOME` if set, or `~/.config/herdr-app` otherwise. Use `--home <directory>` to specify a destination. After installing a theme, select it in Herdr's theme picker.

Herdr updates its built-in mods and layouts. To customize one, first copy it under a new name and have the custom layout reference the custom mod. Symbolic links and hot reload have not yet been verified in this project.

After installation, check priority ordering, the number shortcuts, list, Add, Edit, cancellation, mode selection and long command text in the running app.

Each saved command has a Foreground or Background run mode; existing commands default to Foreground. Background opens a normal terminal tab, then returns to the original tab if the new tab is still selected. Herdr currently selects newly created tabs, so the new tab may appear briefly. If you switch elsewhere during startup, your selection is kept. The command and its output remain available in the new tab. Background mode requires the `herdr-app` command on the local PATH. After updating, verify both modes with a harmless command, including output, failure handling, and switching tabs during startup.

The `nook` layout copies the current Herdr `main` layout and uses the custom `nook-tabs` mod. Select `nook` in the layout picker after installation. For an unnamed tab, the bar chooses the first agent pane, otherwise the first non-shell terminal, otherwise the first terminal, in pane order. It displays the agent's terminal title when available, otherwise the program name, then the current directory's last component, and finally the tab number. A manually named tab always keeps its name; clearing it returns to automatic display. The inferred name is not saved or sent to other clients. Pane focus changes do not change which split supplies the name.

## Spaces and editors

The `nook` layout also uses `nook-spaces`, based on the installed built-in Spaces mod. Expanded rows show the space name, agent status, Git branch, changed-file count, ahead/behind counts and multiple-tab count. Non-repositories show their current folder; `Git unknown` means the result is pending or unavailable, not a clean repository. Git data follows the built-in refresh strategy and can lag behind external edits. The first available terminal folder supplies the Git and editor location. Lucide icons supplied by Herdr are selected consistently from each space ID.

Expanded machine cards show CPU usage and used / total memory in GiB. Linux reads `/proc/stat` and `/proc/meminfo` once every two seconds. CPU is the average between successive snapshots (first sample shows …); idle includes iowait, total includes steal, and guest time is not counted twice. Failure, reconnection, boot-ID changes or decreasing counters reset the CPU baseline. Memory is `MemTotal − MemAvailable`, matching the used/unavailable-memory convention of modern `free`. Hover the metrics row for available memory, buffers/cache (`Buffers + Cached + SReclaimable`) and used / total swap, all in GiB. These details come from the same `/proc/meminfo` snapshot and are not added to the main used-memory value. On each Apple Silicon Mac, install `macmon` (`brew install macmon`, tested with 0.11.0) and ensure `curl` is available. Each Spaces mod instance starts its own `macmon serve --host 127.0.0.1 --port <private-port> -i 2000` on each target Mac, then reads `/json` every two seconds. This uses PATH or the standard Homebrew paths and requires no launchd installation. CPU uses active residency (`cpu_active_ratio`), not frequency-scaled utilization; memory uses `ram_usage` and `ram_total`. Below CPU and MEM, a CPU temperature curve shows five minutes of history on a fixed 0–120 °C scale, with the current value right-aligned in a fixed 60 px card (room for `199.9 °C`), so digit changes do not resize the curve. The curve and value share the same background, border, rounded corners and 27 px height as the CPU and MEM tiles. It begins after two samples, leaves gaps after missing samples, and resets on a failed sample or mod reload. Missing temperature does not prevent CPU and memory display.

The macmon process survives individual reads. Folded cards, a narrow sidebar and inactive windows continue reading JSON and recording temperature history every two seconds, while skipping metric redraws. Switching away from Herdr therefore preserves the curve; actual sampling gaps longer than six seconds still appear as breaks. Each poll renews a private 20-second lease under `/tmp/nook-macmon-<random-token>` on the target machine. A small shell supervisor stops its own child and removes this temporary state when the lease expires, macmon exits, or the mod requests shutdown. Layout removal, reload and normal Herdr exit request shutdown; a crash or unreachable remote machine falls back to lease expiry. Separate mod copies own separate collectors and do not stop user-managed macmon services. The service listens only on loopback; other processes on that machine can read its metrics. Random-port collisions or endpoint errors stop that collector and retry; stale snapshots older than ten seconds are rejected. Linux commands return immediately without a sampling sleep; the per-machine guard prevents overlapping requests.

Run `node tests/machine-metrics.cjs` for Linux counter deltas, resets and memory calculations, parsing, real macmon service samples, process reuse, explicit shutdown and lease expiry (about 32 seconds on a Mac with macmon installed). Run the existing background-refresh and render-performance tests, then `herdr-app check mods/nook-spaces`. Review the installation dry run, apply, and check `herdr-app status` and `herdr-app shot`. In Spaces, verify two-second local updates, the temperature curve after switching away for at least ten seconds, folding/unfolding, a narrow sidebar, layout reload and remote Macs. Set `NOOK_TEST_LINUX_MACHINE=<connected-machine>` when running the metrics test to verify the actual Linux snapshot command and cross-poll CPU delta remotely. Automated local service checks do not establish remote Mac sensor or full-app exit behavior.

Hover over an expanded Space and click its pin to keep it at the top of its machine; click the highlighted pin again to unpin it. Pins are stored in Herdr shared state on this client and survive layout changes and restarts. Pinning changes the display order without changing the saved Space order; drag within the pinned or unpinned group to reorder. A worktree pinned separately from its main checkout is displayed as an independent row. To verify after installing, pin and unpin Spaces on each machine, drag within a group, and confirm the original group position returns after unpinning.

The package-pen icon opens the current folder in an installed VS Code or Zed on macOS. For a remote space, the picker looks up the machine's SSH target in `hc machine ls` and passes the remote path to the selected editor. Both editors must be able to SSH to that target independently of Herdr; VS Code also needs its Remote - SSH extension. The editors may prompt for authentication or install their remote server. SSH config aliases are supported. Custom `hc machine add --via` transports are not supported; use a normal SSH config alias. For VS Code, configure a nonstandard port in SSH config and add the machine with that alias. An absolute remote folder is required. An accepted launch does not mean the editor has connected successfully: check the editor window for connection errors.

The icon is from [Lucide](https://lucide.dev/) (ISC license; see Herdr's `icons/LICENSE-Lucide.txt`).

After updating, review `python3 scripts/install.py --dry-run`, install the changes, and run `herdr-app check` for both `mods/nook-spaces` and `mods/nook-editor`. Check `herdr-app status` and exercise the picker in the `nook` layout. The layout and mods are snapshots of built-in code; compare them with Herdr's updates before incorporating upstream changes.

Right-click a Space and choose **Change icon** to browse the icon grid. The picker reads SVGs from Herdr's `mods/workspace-chrome` and `icons` directories each time it opens. Enter part of a name to filter; Enter selects an exact match or the sole result. Hover an icon to see its name and source. **Random** draws a preview from the current results. Use **Draw again** to redraw and **Use icon** to save the preview; closing the picker leaves the saved icon unchanged. **Automatic** restores the default. The selection is saved per Space in this client's shared state and persists across layout changes and restarts. Nested worktrees keep their branch icon until a custom icon is chosen; the compact sidebar continues to display numbers. Icons are drawn in the Space color.

## Render performance

Background refresh avoids redundant work as well. The 250 ms Spaces poll does not requeue an initial Git query that is already pending or running. Folder-watch events, folder changes and command completion can still request a follow-up while that query runs. Machine discovery allows one request at a time and redraws only when its returned machine list changes. The footer retains its seconds clock but requests timer redraws only while the window is active and the sidebar is wide enough to show the clock (at least 160 px); normal Herdr renders show the current time when focus or layout changes.

Run `node tests/background-refresh.cjs` for delayed Git responses, deduplication, watcher follow-up, machine discovery overlap, unchanged results, failure recovery and clock visibility. Run `herdr-app check mods/nook-spaces` and `herdr-app check mods/nook-footer` as native checks. Install through the dry-run review process above, then check `herdr-app status`. In the running app, verify initial Git data, changes made during a query, machine connection changes and the clock when narrowing or widening the sidebar and returning to the window. These checks do not measure native CPU usage or frame time.

`nook-spaces` shares one snapshot of Spaces, panes, agents, and machine layouts across rows on each render, counting agents by Space once. Each render and 250 ms Git polling pass indexes tab ownership and the first available pane folder in one pass, preserving pane order across multiple tabs and the Space folder fallback. Folder lookup costs O(Spaces + tabs + panes) per pass instead of repeatedly scanning all panes for every Space. Worktree children are indexed by repository, rows by machine, and visible parents by pin group, avoiding repeated full-list scans during grouping. The snapshot is rebuilt on the next render, so live title, status, folder, and connection changes remain visible. Color assignment maintains running usage counts instead of rescanning every assigned color for each candidate. `nook-tabs` selects each tab's preferred terminal in one pass over panes, preserving the first agent, then first non-shell terminal, then first terminal in model order. Manual names keep priority.

Run `node tests/render-performance.cjs` from the project root for render regression checks with a minimal GPUI mock. It covers tab selection, live updates, agent counts, balanced colors, native collection read counts, and linear pane-field read bounds for 1, 100, and 1,000 Spaces. It also checks folder updates, pane order across tabs, worktree grouping, duplicate checkouts, pin partitions, and remote groups. This checks JavaScript behavior and call counts, not native layout, frame rate, or CPU usage. Also run `herdr-app check mods/nook-spaces` and `herdr-app check mods/nook-tabs`.

A before/after comparison using the same GPUI mock and one terminal pane per Space counted reads of each pane's `tab` field (lower is better):

| Spaces | Render before | Render after | Git poll before | Git poll after |
| --- | ---: | ---: | ---: | ---: |
| 100 | 15,150 | 100 | 5,150 | 200 |
| 1,000 | 1,501,500 | 1,000 | 501,500 | 2,000 |

The render also reads the native Spaces collection once instead of twice. These are operation counts, not frame-time or CPU measurements. Structural Space moves still use the existing command and retry path; the optimization targets folder lookup and grouping, not the cost of applying a reorder.

These commands check project sources; they do not install them. To apply an update, review the installation dry run and destination differences using the installation steps above. After installing, check `herdr-app status`, inspect a `herdr-app shot` capture, and exercise tab titles, Space selection, pinning, dragging, editor launch, and remote machine status in the running `nook` layout. Native interaction and performance measurements require that separate runtime verification.

## Files context menu

The Files tree includes a path search and Material Icon Theme file and folder icons (MIT; see `mods/nook-files/LICENSE-material-icon-theme.txt`). Search reads nested folders on the active Space's machine, including folders not expanded in the tree. Click a file result to preview it, or a folder result to reveal it in the tree; the context menu also works on results. Search skips `.git`, `node_modules`, `target`, `.venv`, `__pycache__`, `dist`, and `.next`, and is bounded to 500 entries per folder, 5,000 entries overall, 12 levels and 200 results. It reports incomplete searches and unreadable folders. Search waits 250 ms after typing and builds a shared in-memory path index with at most four directory reads in flight. Query changes reuse that index without directory reads; the local folder watcher and 10-second tree refresh invalidate it. Re-enter or edit the query after refresh to rebuild it. The index is scoped to the current machine and working directory and is not written into the project. Plain text matches any part of a path, ignoring case. Wildcard patterns match whole basenames at any depth when they contain no slash (for example `*.js` or `file?.txt`); patterns with slashes match root-relative paths (`src/*.js` for immediate children, `src/**/*.js` for any depth). `*` matches zero or more non-slash characters, `?` one non-slash character, and `**` crosses folders; `**/` also matches zero folders. Other characters are literal. Results appear when indexing finishes. Run `node tests/files-search.cjs` for matching, index reuse, bounded concurrency, limits, read failures and cancellation checks. Directory links follow the same behavior as the normal tree, subject to these bounds.

The tree shows the current Git branch and a colored indicator after changed file and parent directory names. Untracked files use a hollow blue circle, while other changes use a filled dot: green for added, yellow for modified, and red for deleted or conflicted, using the active theme's ANSI colors. The name uses the same status color; hover the indicator to see the status. A directory with several kinds of changes shows one of its children's statuses. Git data refreshes with the existing file-tree polling and local folder watch; it may lag external changes. Deleted files are represented by their parent directory when the file is no longer present. Search and Git status operate on the focused terminal's current folder, including supported remote machines.

In the expanded file tree, Git-ignored files and folders use dimmed names; hover the name for its status. Git checks the visible entries against the repository's ignore rules, including nested rules and exceptions for tracked files. This uses `sh` and `git` on the active Space's machine; if the check is unavailable, entries keep their normal appearance. Search results are marked when their containing folder has already been loaded in the tree. Refresh follows the tree's folder watcher and polling. After installation, check ignored and tracked files, folder expansion, ignore rule changes, and the branch icon in the running panel.

The `nook` layout uses `nook-files`, a snapshot of Herdr's Files panel. The search and branch row serves as the file tree's header, with a bottom border matching the Preview header. The file tree stays above a read-only preview; select a file to show it below and drag the divider to resize the two areas; its last ratio is restored when the panel is reopened. Markdown and SVG files offer Code and Preview modes; each kind remembers its last chosen mode for this panel across files and app restarts. Both modes use the same bounded file content. Right-click a file or folder to open it in Zed or VS Code, or copy its path relative to the folder shown by Files (the focused terminal's current folder). The menu supports arrow keys, Enter and Escape. Opening uses the local macOS editor; remote paths use the same SSH target restrictions described above for Spaces. The editor may still need to authenticate or establish its remote connection.

The same menu offers Insert Relative Path: focus the target terminal first, then right-click a file or folder and select the action. It pastes the path relative to the Files root at the terminal's current cursor, with one space on each side and without pressing Enter; the padded path replaces the system clipboard contents. If the target terminal changes while the menu is open, reopen the menu from the intended terminal. After installation, check insertion into an existing draft, including paths with spaces and non-ASCII characters, and verify that it does not submit the draft. Also check split panes and remote terminals when used.

The Preview title shows the full relative path when it fits and truncates from the left when needed. Its insert button sits before the Code and Preview controls when they are available, and inserts the selected file path using the same action. Hover a file row to reveal the same insertion action after its name and Git status indicator. Clicking it does not select or preview the file. Verify the button on ordinary and search-result rows, including long filenames and Git status indicators.

The fixed-width search field in the preview title bar finds literal text without case sensitivity in the loaded text preview, including Markdown source in either mode and SVG source in Code mode. Results show matching lines, line numbers, and the first match on each line; at most 200 lines are displayed, with the total shown. Clear the field to return to the preview. The search is limited to the loaded preview (up to 400,000 characters) and resets when selecting another file. In SVG Preview mode the field appears only when the image cannot be loaded and the source is shown instead. Images and binary files do not offer text search. Run `node tests/preview-search.cjs` for search checks; after installation, verify results, clearing, Markdown modes, SVG modes, and switching files in the running panel.

After updating, run `python3 scripts/install.py --dry-run`, review any destination differences, and install with `python3 scripts/install.py`. Run `herdr-app check mods/nook-files` and `herdr-app check mods/nook-files-menu`, then check `herdr-app status`. In the `nook` layout verify search in collapsed directories, result previews and folder navigation, icons, Git branch and status, the menu on nested files and folders, clipboard contents, both editor launches, remote paths where applicable, file preview, split resizing, and folder expansion. Compare the snapshot with Herdr's built-in Files mod when incorporating upstream updates.

On macOS, selecting a local PNG, JPEG, GIF, WebP, BMP or SVG previews the original file. Herdr loads application-relative assets, so the panel stores byte-for-byte copies under `data/nook-files-originals/` in the active Herdr configuration directory. All projects share one cache of at most 16 files, including SVGs. Selecting a previewable file makes it the most recently used; adding another file beyond the limit removes the least recently used cached file. Files with identical bytes and the same extension share a cache entry. Switching files or closing the panel does not clear the cache. The panel does not resize or re-encode raster images; `sips` reads their dimensions and the UI fits them proportionally. For SVG, the panel reads `width`, `height` and `viewBox` from the root element instead of using `sips`; missing, percentage or non-pixel dimensions fall back to the viewBox, then to the SVG defaults of 300×150. SVGs larger than 5 MiB, malformed XML, and SVGs with document type declarations fall back to source. SVGs render in full color with transparency; scripts and animations do not run, and references to external files or fonts are not resolved. The Code mode still shows the source; when preparation fails, the panel shows the source and disables Preview. Remote SVGs keep the text preview, as do SVGs on other platforms; remote raster images show an unavailable message. This image pipeline requires macOS and `python3`. Native decoder support determines which images render. Herdr does not report image decoder failures to the mod, so a well-formed SVG that the decoder cannot render may appear blank; switch to Code to inspect it. Animation playback has not been verified. Older thumbnail experiments used `data/nook-files-previews/` and are not part of this cache. Run `node tests/files-preview.cjs` for preview modes, remote and fallback branches, and `python3 tests/image-cache.py` for SVG dimensions, byte copies, extension handling, size limits and LRU eviction.

After updating, select images and `layouts/nook.svg` in the running panel and inspect a `herdr-app shot` capture, resize the split, switch between SVG Preview and Code, and switch back to text and Markdown files. Also check a viewBox-only SVG, a percentage-sized SVG, transparency, a broken SVG falling back to its source, the remote text fallback, and eviction after selecting more than 16 previewable files. To verify original-file preservation, compare the source and temporary copy with `cmp` or SHA-256.

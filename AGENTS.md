# Nook Project Guide

Nook manages personal customizations for Herdr App, including themes, mods, and layouts. Start by reading the relevant sections of the project README and `~/.config/herdr-app/AGENTS.md`. The latter is generated by Herdr and describes the capabilities of the installed version.

## Directories and configuration

- `themes/` contains themes, `mods/` contains custom mods, and `layouts/` contains custom layouts.
- This project and `~/.config/herdr-app/` are separate directories. Changes in the project are not automatically applied to Herdr unless a synchronization method has been set up and verified.
- Before applying changes to Herdr, inspect the destination and any existing modifications, and preserve user data. Do not edit Herdr's built-in mods or layouts directly: copy them under new names and have custom layouts reference custom mods.
- Do not assume Herdr's file watcher handles symbolic links correctly. Verify loading and hot reload before relying on them.
- Do not stage, commit, or clean up user changes without permission.

## Implementation and verification

- Before making changes, trace the actual data sources and scope through the current layout, mods, and Herdr API. Preserve existing functionality and manual settings where possible.
- After changing a theme, validate its JSON. When applying it, check `herdr-app status` and configuration errors. For visual changes, inspect the window with `herdr-app shot` and identify any states that were not checked.
- After changing a mod, run `herdr-app check <mod-directory>` and verify the relevant interactions in the running app. The check does not replace testing the actual layout and interactions.
- After changing a layout, validate its JSON and inspect the layout, mod references, and relevant interactions in the app.
- Document how to install, update, and verify changes. Clearly distinguish project source files, applied configuration, and effects that have not yet been verified.
